## Wide mode after the upstream merge (agreed 2026-11-20, done 2026-11-21)

- **Upstream 1.3.0's new screens work in wide mode:** the AUDIO DRIVERS overlay, the Studio synth XY pad page, the per-family synth sheets, the frog stage and karaoke, and the lyric keyboard. Dialogs are centred like ours (`wide_dx()`), and XY pad touch maps correctly on the wide canvas. Extend `ptwide-mode-check` to cover them.
- **Wide mode stands alone,** so upstream can take it without anything else:
  - **With or without the VI visualizer:** wide mode widens VI when VI exists, and builds and works when it doesn't.
  - **With or without sharp scaling:** wide mode works with integer scaling alone, and uses SCALING only when that row exists.

  Each combination must build: with both, with either one, and with neither.

  **Checked 2026-11-21:** with both (our `main`): builds, `ptwide-mode-check` passes. With neither: wide mode applied on plain upstream 1.3.0 (`origin/main`, which has no VI and only its own INT / BILINEAR SCALING row) builds with MSVC, and every check passes except the five exact-pixel hashes, which upstream's own screens change. Not built separately: VI alone and sharp scaling alone, as they are halves of those two builds. What porting wide mode to upstream needs:
  - **VI:** set `vi` to `false` in `layout.cpp` (marked) and drop the VI lines in `wide_mode.cpp` (marked). ⚠️ The full-width scope band uses `OscilloscopeModule::draw_sized`, which came with VI's commit `fddc165`: that part of `oscilloscope.h/.cpp` must go with wide mode.
  - **SCALING:** wide mode needs nothing from sharp scaling; the video code sizes from `DESIGN_W` in both. Only the SETTINGS order line (marked) and `portrait.layout`'s last argument (upstream's `scalingBilinear`) differ.

## More visualizers: split from wide mode after the upstream merge (agreed 2026-11-20, done 2026-11-22)

More visualizers (item 20) and wide mode (item 10) are separate features. Upstream may take either one without the other, and nothing may break.

- **The split, done right after U:**

  2. Wide mode's own check (`ptwide-mode-check`) draws every visualizer style the app has at 16:9 and checks each stays in its box, reading the list from `SettingsModule::visualizer_names()`, so it passes with the original 9 styles or all 23.
  3. Each branch builds and passes CI alone, and both merged together too. Neither contains code that knows about the other.
- **Split done 2026-11-21** on branch `more-visualizers-2`, cut from `main` (which now has wide mode): one commit makes `ptwide-mode-check` draw every style at 16:9 from the app's own list, and one commit adds the 14 styles with a 4:3-only `ptvisualizer-check`. For an upstream PR without VI: the styles fill the box they are given, but they reach the screen through `OscilloscopeModule::draw_sized` (`w_`, `h_`, VI's commit `fddc165`) and the stopped clock `demoMs_` (commit `3bc4261`); without those, use `WIDTH` / `HEIGHT` and the animation clock.

## Later (no spec yet)

Ordered 2026-11-20: file safety, then the screen shape, quick wins, the sound foundations, Windows parity and help, then the synth groundwork before any new synth model. The rest keeps its earlier order.

- **Drumlab: per-step chance, ratchets and pitch:** `CHA`, `RPT` and `PIT` per step in Drumlab's Step Edit, after [drumlab-manual.md](drumlab-manual.md).
- **Chords on synths:** `CHD` plays its chord on the chord engines (P CHORD, P STRING MACHINE, G CHORD SWARM): one engine plays the chord's notes, taken from the same chord list as samples (snapped to the scale, with the voicing). 4 notes. Every other synth stays as today (root note only). Plaits' chord engine and G CHORD SWARM have built-in chord tables to replace with the chord's notes.
- **Synth stereo output (agreed 2026-11-19):** a synth can hand the voice two channels instead of one (today `synth.next` returns one value, so every synth is mono). A stereo synth uses the instrument chain's existing stereo path (the one stereo WAVs and SoundFonts use: `chain.processStereo` in `engine-mix.cpp`); mono synths stay exactly as today, at the same CPU. First users: the electric piano's tremolo pan and the organ's rotary speaker (next item), then Rings and Elements, which already make stereo. Any future stereo synth plugs into the same path.
- **Advanced Synth Studio (agreed 2026-11-19):** the Studio's synth page stays as it is (model, preset, macros); an ADVANCED button opens only the loaded synth with its full controls, on as many pages as it needs: what a professional VST3 would expose, every control that changes the sound and nothing purely technical. Known gaps: editing FM SYSEX's six operators, and Plaits' built-in envelope to timbre, morph and FM (fixed at zero today). The spec decides whether envelopes, LFOs or phrase commands may move synth controls (not possible today), and grows the song's synth settings past today's 16 per instrument so old songs load and sound the same. The same values give the same sound as today's rows; only controls fixed in the code today add new sound. **One set of values (agreed 2026-11-19):** the Advanced page shows everything for that synth, including what the main Studio pages already show (macros, engine params, and the instrument's filter, drive, level, pan, tune and ADSR, which are the instrument's own settings, the same values as on INSTRUMENT and MODS), and both pages edit the same values, so a change on one shows on the other and no switching back is needed. A synth's own envelopes (DX7 operator envelopes, Plaits' LPG decay, DCO POLY's envelope) are separate controls that act before the instrument's ADSR, and the page labels them so. Both FM SYSEX and the Dexed DX7 get their full controls here. **Synth control commands (agreed 2026-11-19):** phrase commands that set a synth's macros A/B/C and its params from a phrase step (absolute), with optional smoothing, so timbre, morph and the rest can move inside a song; ChooChooTracker (MIT, read 2026-11-19) has one set per engine (Braids `BMD/BTM/BCL`, Plaits `PMD/PHA/PTM/PMO/PAX`, Plaits trigger decay and colour `TDC/TCL`, FM operator commands, and so on). The spec decides one generic set (macro and param number) or per-engine sets, and the engines imported from ChooChooTracker (MIT, read 2026-11-19) bring their commands along.
- **More mod targets (agreed 2026-11-19):** the instrument's 4 mod slots (LFO, ADSR, AHD, DRUM, TRIG, TRACKING, SCALAR; `songcore/model.h`) can today move volume, pan, pitch, fine pitch, filter cutoff and resonance, sample start and another mod's amount or rate. Add targets: **reverb send, delay send, drive, crush** (and EQ if the spec finds it cheap), and **synth macros A/B/C and synth params** (with the Advanced Synth Studio's synth control work). Each new target is wired into the existing per-voice mod path, smoothed so it never clicks, and named in the MODS screen and its help. Until then, tables with `REV`/`DEL` and the other commands are the way to sweep sends. The spec decides whether track faders and mixer settings become targets too (they are per track, not per note), and checks the CPU cost of synth-param modulation on the weakest handheld.
- **Sample editor gaps (found 2026-11-20, to brainstorm):** compared with Polyend Tracker, M8, picoTracker/LGPT, Digitakt, OpenMPT and Schism (from knowledge; (?) = unverified). Missing: multi-level undo/redo (medium; capped on handhelds); loop points drawn and edited on the waveform instead of 0-255 instrument fractions (medium); loop crossfade for click-free sustain loops (medium); fade curves (exp/log) and crossfades at cut/paste joins (small); mix-paste and paste-over (small); insert silence and auto-trim silence (small); more destructive effects: filter LP/HP/BP, reverb, delay, chorus/flanger, compressor/limiter, as in Polyend (medium each; reuse the engine's); threshold-triggered recording with input gain and monitor (medium; check the recorder first); resample to an explicit rate such as 22.05k/11k (small); free varispeed in cents outside SYNC (small); draw mode for single-cycle waves (medium, low priority); mono to stereo and L/R swap (small); wavetable export, ties to P WAVETABLE bank 4 (medium); slices written into a phrase as one note per step (medium, (?)).
- **Tempo-change command `TPO` (agreed 2026-11-19):** a phrase command that sets the song tempo from that step (for ritardandos, section changes, half-time drops); the MOD, XM and IT importers need it for their speed and tempo commands. None of our 53 commands changes tempo today (grooves only change swing), and ChooChooTracker (MIT, read 2026-11-19) has none either. Small. Help: its SELECT and FX help entries and the manual.
- **Phrase commands from ChooChooTracker (agreed 2026-11-19):** ChooChooTracker (MIT, read 2026-11-19) has 179 commands against our 53; most are tied to its own synths and chips and arrive with those items (see the synth items, layer, inserts, Advanced Synth Studio). The general ones we lack, each added with its SELECT help, FX helper line and manual entry, names to be settled in the spec: **VSL** volume slide (changes volume by an amount per step, continuously); ~~PRO probability~~ (taken from upstream 1.3.0 as **PRB**, code 0x40, xx/256 chance); **RNN** random note (plays a random note: mode and range); **RNS** random slice (plays a random slice in slice mode); **EUC** Euclidean retrigger (X hits spread over Y+1 rows, looping, until a new note, OFF, KIL or EUC); **REP / RTO** repeat the previous FX with a signed step per row, between limits (ramps without typing every row); **SPD** per-track speed (×1, ×2, ÷2, kept until the next SPD: half-time or double-time on one track); **SLE** smoothing for parameter changes (00 instant, else a glide in ticks, for synth and engine commands); **GGR** global groove (one groove for every track at once; ours `GRV` is per track); **SNG** song hop (jump N rows in the song); **TBX / TXH** a second, auxiliary table per note and its hop (two tables running at once); **TPN** track pan (sets the track's mixer pan, kept until changed; ours `PAN` is per note); **EAT / EDC / ESU / ERL / ESH** envelope attack, decay, sustain, release and shape for this note; **M1A-M4x** modulation slot commands (offset a mod slot's amount and its parameters); **MRT / MKL** retrigger or stop chosen modulation slots; **SEN** sample end for this note; **SLP** sample playback mode for this note (forward, reverse, loop, ping-pong); **SSP** sample speed 0-500 %; **NOF** note release after N ticks (their `OFF`; ours `KIL` cuts, so the spec checks whether a soft release command already exists before adding it). Already covered by ours (not added): RET → `RPT`, DEL → `LAT`, SST/STA → `OFF`, SCL → `SCA`/`SCG`, CRD → `CHD`, BEG/END → `AUS`/`AUF`, RSN/DSN → `REV`/`DEL`, MC1-4 → `CCA`-`CCD`, MOD → `NTH` (the spec checks NTH covers pass A of B), PIT, FIN, VOL, PAN, SLI, NTH. Their help text (`tracker/src/screens/help.cpp`) is a reference for ours.
- **Maqam microtones (agreed 2026-11-19):** each scale note's cents offset, already stored in songs and `.pts` files (`Scale::offset`, `songcore/model.h`, −2400..+2400 cents) but not played or shown today, becomes real. A note snapped by a scale plays with its degree's offset: exact on samples (each chord note too, through its own ratio) and on synths (they take a frequency); SoundFonts through TinySoundFont's per-channel tuning (`tsf_channel_set_tuning`, one channel per track), where a chord shares one tuning and a release tail shifts when the next note retunes, unless the spec adds a guarded per-note tuning to TinySoundFont; external MIDI only approximately (pitch bend). The SCALE screen gains a cents column per note. NAME gains maqam presets (Rast, Bayati, Saba, Sikah, Huzam, Hijaz, Nahawand, Kurd, Ajam and others) with standard offsets that can be adjusted for regional intonation. Phrases mark notes that sound shifted. Chords (`CHD`, the chord editor) follow the scale's offsets. A scale holds one version of each note; maqams that change mid-passage switch scales with `SCA`. Old songs are unchanged (every offset 0). The spec decides how the cents travel from the sequencer to the voices (notes are whole semitones there today; the event layout is checked against goldens) and writes the help.
- **Chord swarm engine (Hypersynth-style):** a new synth model that runs one Braids SAW SWARM (already vendored, MIT; 7 detuned saws, JP-8000 layout) per chord note: 4 notes, 28 saws. It reads `CHD` like the other chord engines (needs "Chords on synths" first). Knobs: detune (the swarm's own), brightness (its filter), stereo spread across the chord. A thin wrapper around existing Mutable code, like TrackWerk's other models, not a synth written from scratch.
- **Synth: acid bass (agreed 2026-11-18):** a TB-303-style model from **Open303** (Robin Schmidt, MIT): its filter, accent and slide, light on CPU (about one oscillator and one filter per note). Slide maps to the existing pitch slide or legato; the spec decides how accent is written (a phrase command or velocity). Licence and CPU confirmed in the spec; notice in THIRD-PARTY-NOTICES. **Shortcut:** ChooChooTracker (github.com/paiheulevrai/Choochootracker, MIT, read 2026-11-19) ships Open303 and an acid voice built on it (`chipnomad_lib/synth/achchid_voice.cpp`: Open303 filter, Braids oscillators, a soft-clip-to-fold shaper, accent and slide), a model for this item. - **New Note Action (Impulse Tracker style):** what a note does when the next one starts on its track. Separate from the later voice-capacity setting in Settings (how many voices a device may use), which decides how many background voices there are.

NORMAL (the default) is exactly today's 8 song voices plus the preview voice, so small handhelds and existing songs are unchanged; higher steps let stronger devices (Windows, Android, strong handhelds) use more CPU. A device setting, not saved in the song. It pays for New Note Action's background voices and, later, chords on synths beyond the chord engines; when full, the quietest voice is dropped instead of the sound breaking up. The spec decides the steps per platform and whether the app warns when a song wants more voices than the device allows.

OFF (the default) is today's mix. ON renders the selected tracks with no reverb or delay returns, no master EQ, OTT, DUST or Studio master rack, no PERFORM filter and no master fader; it keeps the instruments' own sound and the track faders, and the safety limiter (the file is 16-bit). The box remembers its rows between uses. The status says `RESAMPLED DRY -> INST xx` when DRY was on.

- **Live stick (agreed 2026-11-19, widened 2026-11-22):** a handheld's or gamepad's analogue sticks as performance controllers (filter, macros, PERFORM targets), as in ChooChooTracker (MIT, read 2026-11-19) (`chipnomad_lib_live_stick.*`). **Every stick the device has** can be assigned, one or two (or more if a controller reports them), each on its own; a device with none shows nothing. **Any target**, including upstream 1.3.0's Studio synth **XY pad** (a stick's X/Y moving the dot, the same two macros the pad sets), which did not exist when this was agreed. The spec maps the sticks onto PERFORM's controls and the XY pad, and settles how a stick is assigned and what happens when a controller is unplugged.
- **Automation recording (agreed 2026-11-19):** with record armed and the song playing, moving a mapped knob writes its movement into the playing phrase as that parameter's command on each step it passes, so playback repeats it; smooth stretches can be tidied into an `AUS`/`AUF` ramp. Works with MIDI controllers learned with R + knob (`songcore/midi_map.h`) now, and with the handheld's analogue stick once "Live stick" exists. Records anything a knob can be learned to and a phrase command can set (today: volume, pan, sends, track and master faders, filter, drive, fine tune, delay time, EQ slots; later the envelope, synth control and insert commands). Today knob moves change the live value only, and PERFORM's controls are not recorded. The spec handles: one value per step (finer movement belongs in tables), the three effect columns (never overwrite the user's commands: use a free column or warn), phrases used elsewhere in the song (warn, or record into a copy), undo through PHRASE's history, and whether PERFORM's knobs record too.

- **16 tracks (agreed 2026-11-18, redesigned 2026-11-19):** a song is either 8-track or 16-track; there is no device setting for it. **File extension:** 8-track songs stay `.ptp`; 16-track songs save as **`.pt16`** (any extension length works on Windows, macOS, Linux, Android and FAT32/exFAT cards with long names). Older TrackWerk versions list only the extensions they know, so they never see a `.pt16` and can't open or damage it. The app opens both and switches to the song's track count as it loads. **NEW** asks 8 or 16 tracks in a small box. **PROJECT** gains a TRACKS 8/16 row next to the song's name: 8 → 16 turns tracks 9-16 on and the song saves as `.pt16` from then on (the earlier `.ptp` stays as it was); 16 → 8 is allowed only after one short warning, shown only when something would go: `SONG MAY NOT SOUND THE SAME. YOU WILL LOSE:` followed by only the lines that apply (`TRACKS 9-16`, `FX4-5`, `PHRASES ABOVE FF`, `CHAINS ABOVE FF`, `CHD²/³ CHORDS`); A converts and deletes them, B changes nothing; a 16-track song may stay `.pt16` even with tracks 9-16 empty. In an 8-track song tracks 9-16 show greyed (see wide mode). **Same name, two extensions:** `Song.ptp` and `Song.pt16` may exist side by side; every name check (save-over question, COLLECT, rename) and the autosave treat `.pt16` exactly as `.ptp` today, each within its own extension, and the autosave writes the extension of the song that is open. **Pools (16-track songs only):** 512 phrases and 512 chains (8-track songs keep 256), 256 instruments and 256 tables (still two hex digits). Screens with room show phrase and chain ids as three hex digits (CHAIN's PH column, PHRASE and CHAIN titles; leading zero dimmed); SONG keeps two characters by letting the first one run on past F: `G0`-`VF` mean `100`-`1FF` (G = 10 … V = 1F), drawn with the app's own letters. 512 is the ceiling (two characters can't name more). Windows, Linux desktop and Android open it directly. **Pages:** SONG, MIXER and any screen whose tracks don't fit (on 4:3, or past the screen's width) show them a page at a time; moving the cursor past the last track on the page turns to the next page, the way the screen map's letters move between screens, and a small arrow on the left or right shows there is another page that way. Open for the spec: what the preview lane (today track 8 + 1) becomes, MIDI and stems for tracks 9-16, and the voice count (16 song voices + preview). Mapped earlier: about 120 places in the code assume 8 tracks; the song format already allows any number of tracks, and phrase / chain refs are plain integers. **Five effect columns (agreed 2026-11-19, 16-track songs only):** PHRASE gets FX4 and FX5 in `.pt16` songs (8-track songs keep three). ## Optimisation (agreed 2026-11-22)

From the RG505 measurements (2026-11-22): at full CPU speed an 8-voice song uses 17-26% of each audio block, but 85-106% on the lowest power setting, and upstream's official 1.3.0 behaves the same. The XY pad's crackle is not CPU (about 6% load) but values jumping. Our features (wide mode, visualizers, sharp scaling) are not the cause. The synth engines keep their native sample rates; savings come from the items below, in this order. Each gets its own spec when started. Related: "Synth voices on spare cores" in Later.

1. **Measure the sound engine:** a timing tool that shows what each part costs (each synth model, reverb, delay, filters, drive) on a real song, on Windows and the RG505. Every later item targets what it finds.
2. **AUDIO: FAST / SAFE / AUTO (Android):** FAST is today's low-latency path (2 bursts, about 20 ms of reserve). SAFE uses a bigger buffer or Android's normal audio path, as Caustic does. AUTO picks SAFE on Bluetooth (about 200 ms of delay anyway) or when late blocks are detected, FAST otherwise. Small: the normal path is already the fallback in `oboe-audio-engine.cpp`.
3. **Soft cut instead of a click:** when an audio block arrives late, fade out and back in instead of a hard jump, so overload sounds like a short cut.
4. **Android performance hint:** tell Android how much work the audio thread needs, so it keeps the clock up or uses a big core (check which Oboe version offers it).
5. **Draw less often while playing:** cap moving visualizers at about 30 frames a second on slow devices, or as a setting; roughly halves the drawing's CPU during playback.
6. **Voice cap on tails:** when too many notes overlap (chords, long releases), fade the quietest, nearly finished tails a little earlier.
7. **Stop silent synth voices:** stop computing a synth voice once its output stays below hearing level for a moment, like the send buses' idle sleep; the engines themselves are not changed.
8. **Smooth XY pad and macro moves:** let synth values glide over a few milliseconds instead of jumping, which removes the zipper crackle. Upstream's code: a candidate bug-fix PR.
9. **Use the synths' stereo outputs:** Plaits and Rings compute a second (aux) output that the voice drops today (mono, `procR = procL` in `engine-mix.cpp`); using it gives wider sound for almost no extra CPU. Fits Advanced Synth Studio.
10. **Per-instrument CPU meter and cost settings (Advanced Synth Studio, after item 1):** show how heavy each instrument is, and gather the settings that decide cost (Rings polyphony 1/2/4, voice and grain counts) in one place, marked as affecting CPU.
11. **Stress-test song before 16 tracks:** a heavy song (many tracks of the heaviest instruments), measured at each power level on the RG505, for the real worst case before the 16-track item.
12. **Lighter reverb option, only if item 1 shows the reverb is a hot spot:** a cheaper version of the big reverbs for live playback with the same settings; export keeps the full one.

Dropped: changing sample rates (global, or Braids at 48 kHz: too much work, the engines stay as they are); reverse engineering Caustic (no gain, the techniques are known); PADsynth (optional, pads already exist); shared per-instrument effects (covered by "Per-track insert effects"); switching to Caustic's buffering for everything (low latency stays the default, SAFE covers the rest).
