## Later (no spec yet)

- **Audit fixes, batch 2 (save safety):** AUDIT.md findings 8, 10, 11, 12, 19. Finding 8 as agreed 2026-11-17: no copy fallback; retry the rename for about a second; if still stuck, save the song as `<name>-backup.ptp` beside it (loadable from LOAD), keep the original untouched, and say so on the status line.
- **Audit fixes, batch 3 (the rest):** findings 13, 14, 15 (Linux streaming), 18 (Windows README), 20 (note queue on the audio thread: reserve 1024, as the audit says). Also the audit's three "left out (smaller)" findings: the note-queue cancel-ledger off-by-one (`note-queue.h`, `>` → `>=`), the slice-marker overflow (`project_io.h`), and orphan WAV temp files never cleaned up on Windows (`wav_writer.h`). And two help-text gaps: SONG's help gains "A,A on a selection resamples it", PHRASE's help says B+LEFT/RIGHT goes to the next track's phrase (under NAV = SONG).
- **Sound: master limiter (agreed 2026-11-18):** replace the always-on DaisySP limiter (`effects/primitives/daisysp/limiter.cpp`). Today it scales the whole mix by 0.7 and runs every sample through a soft-saturation curve, so a full mix leaves about 4 dB under full scale and slightly coloured; it reacts in under 0.5 ms with no look-ahead (bass distortion), releases over about 1 s (pumping), and limits left and right separately (the image shifts). New: a stereo-linked look-ahead limiter with its ceiling near 0 dBFS, transparent below it. Measure a real render first to confirm the -4 dB. The spec decides whether old songs can keep the old sound. Renders change, so the golden recordings are re-recorded.
- **Sound: sample interpolation (agreed 2026-11-18):** sample playback reads with linear interpolation (`sampler-voice.h` `Playhead::read`), so samples pitched up alias and pitched down go dull. A SETTINGS row picks the interpolation: 4-point Hermite (the new default), today's linear, and OpenMPT's modes (none, cubic spline, 8-tap sinc, 8-tap sinc with low-pass). OpenMPT's resampler code is BSD-3 (fits GPL-3; its notice goes in THIRD-PARTY-NOTICES) and is ported only where it fits the float mixer. The downsample effect keeps its own quantized read. The spec decides how renders and goldens pick the mode, and checks the sinc modes' cost on the weakest handheld.
- **Sound: oversampled drive:** the DaisySP overdrive runs at the base rate, so high notes through heavy drive alias. Run the drive stage at 2x with a small up/down filter pair. The spec checks the CPU cost on the weakest handheld.
- **Save under a new name (agreed 2026-11-18):** when SAVE would write over an existing file (songs: only a *different* song, never the open one), ask `<THING> EXISTS - OVERWRITE?`. A overwrites. B opens the on-screen keyboard to type a new name; saving it goes through the same check again. Cancelling the keyboard goes back to where SAVE was pressed: nothing saved, nothing changed. No automatic `-2` numbering. One rule for **every save that writes a file**: songs, instrument presets (`.pti`), themes (`.ptt`), scales (`.pts`), grooves (`.ptg`), reverb (`.ptr`), delay (`.ptd`), and chords when the chord editor exists. Also a FILE RENAME onto a name that is taken. Fixed-name saves (the template, Studio's custom FX/master slots) and COLLECT (already asks) are reviewed in the spec. Sample SAVE-AS and RESAMPLE stay as they are (they number their files).
- **Chords on synths:** `CHD` plays its chord on the chord engines (P CHORD, P STRING MACHINE, G CHORD SWARM): one engine plays the chord's notes, taken from the same chord list as samples (snapped to the scale, with the voicing). 4 notes. Every other synth stays as today (root note only). Plaits' chord engine and G CHORD SWARM have built-in chord tables to replace with the chord's notes.
- **Chord editor:** the song's 16 chords become editable song data on a CHORD screen built like SCALE (next to SCALE and GROOVE): a NAME row cycling the built-in chords (kept as presets, `*` when edited), SAVE and LOAD of chord files (with the new-name rule above), one row per note. 4 notes. A song with no chord data loads today's 16 shapes in today's order, so old songs sound the same. `CHD`, HARMONY and chords on synths all read the song's chords. One built-in chord list for the whole app: today's 16 shapes plus the ones only Plaits' chord engine has (octave, fifth, 6/9, spread major 10th, dominant 7 flat 9, half-diminished, fully diminished, as 4-note shapes), offered as NAME presets; the 16 song slots still start as today's shapes in today's order.
- **Chord swarm engine (Hypersynth-style):** a new synth model that runs one Braids SAW SWARM (already vendored, MIT; 7 detuned saws, JP-8000 layout) per chord note: 4 notes, 28 saws. It reads `CHD` like the other chord engines (needs "Chords on synths" first). Knobs: detune (the swarm's own), brightness (its filter), stereo spread across the chord. A thin wrapper around existing Mutable code, like TrackWerk's other models, not a synth written from scratch.
- **New Note Action (Impulse Tracker style):** what a note does when the next one starts on its track. Two INSTRUMENT rows: `NNA` CUT (default, today's behaviour) / OFF (plays its release) / FADE / CONT (keeps playing), and `DUP` (what the same note again does: off / cut / release / fade, so pads and hi-hats don't pile up). One new phrase command `NNA xy`: x acts on the notes already ringing in the background on this track (leave / cut / release / fade), y overrides the instrument for this note. `OFF` and `KIL` keep acting on the current note only (to confirm in the spec). Old notes ring in background voices; when there are none free, the quietest is dropped. Separate from the later voice-capacity setting in Settings (how many voices a device may use), which decides how many background voices there are.
- **Voice capacity setting (future):** a SETTINGS row for how many voices this device may play at once. NORMAL (the default) is exactly today's 8 song voices plus the preview voice, so small handhelds and existing songs are unchanged; higher steps let stronger devices (Windows, Android, strong handhelds) use more CPU. A device setting, not saved in the song. It pays for New Note Action's background voices and, later, chords on synths beyond the chord engines; when full, the quietest voice is dropped instead of the sound breaking up. The spec decides the steps per platform and whether the app warns when a song wants more voices than the device allows.
- **Resample options box + DRY:** RESAMPLE (a SONG selection, then A,A) first opens a small options box, then the name keyboard as today. This item builds the box and its first row, `DRY` OFF/ON. OFF (the default) is today's mix. ON renders the selected tracks with no reverb or delay returns, no master EQ, OTT, DUST or Studio master rack, no PERFORM filter and no master fader; it keeps the instruments' own sound and the track faders, and the safety limiter (the file is 16-bit). The box remembers its rows between uses. The status says `RESAMPLED DRY -> INST xx` when DRY was on.
- **Resample: normalise on render:** a row in the resample options box, `NORMALIZE` OFF/ON (OFF by default). ON raises the finished sample to a peak target (the sample editor's Peak Normalize, -1 dBFS unless the spec decides otherwise), so no trip to the sample editor.
- **Resample: load as instrument:** a row in the resample options box, `LOAD INST` ON/OFF (ON by default, today's behaviour). OFF only writes the WAV to the Resampled folder and leaves the instruments alone, with a status that names the file.
- **Resample: bit depth (agreed 2026-11-18):** a row in the resample options box, `BITS` 16 (default, today's) / 24 / 32F, the artist's choice. 16-bit gets TPDF dither instead of today's truncation (`songcore/wav_writer.h`). The spec decides whether the song's WAV export gets the same choice.
