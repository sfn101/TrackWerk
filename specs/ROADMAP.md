## Later (no spec yet)

Ordered 2026-11-20: file safety, then the screen shape, quick wins, the sound foundations, Windows parity and help, then the synth groundwork before any new synth model. The rest keeps its earlier order.

- **Drumlab: per-step chance, ratchets and pitch:** `CHA`, `RPT` and `PIT` per step in Drumlab's Step Edit, after [drumlab-manual.md](drumlab-manual.md).
- **Chords on synths:** `CHD` plays its chord on the chord engines (P CHORD, P STRING MACHINE, G CHORD SWARM): one engine plays the chord's notes, taken from the same chord list as samples (snapped to the scale, with the voicing). 4 notes. Every other synth stays as today (root note only). Plaits' chord engine and G CHORD SWARM have built-in chord tables to replace with the chord's notes.
- **Synth stereo output (agreed 2026-11-19):** a synth can hand the voice two channels instead of one (today `synth.next` returns one value, so every synth is mono). A stereo synth uses the instrument chain's existing stereo path (the one stereo WAVs and SoundFonts use: `chain.processStereo` in `engine-mix.cpp`); mono synths stay exactly as today, at the same CPU. First users: the electric piano's tremolo pan and the organ's rotary speaker (next item), then Rings and Elements, which already make stereo. Any future stereo synth plugs into the same path.
- **Advanced Synth Studio (agreed 2026-11-19):** the Studio's synth page stays as it is (model, preset, macros); an ADVANCED button opens only the loaded synth with its full controls, on as many pages as it needs: what a professional VST3 would expose, every control that changes the sound and nothing purely technical. Known gaps: editing FM SYSEX's six operators, and Plaits' built-in envelope to timbre, morph and FM (fixed at zero today). The spec decides whether envelopes, LFOs or phrase commands may move synth controls (not possible today), and grows the song's synth settings past today's 16 per instrument so old songs load and sound the same. The same values give the same sound as today's rows; only controls fixed in the code today add new sound. **One set of values (agreed 2026-11-19):** the Advanced page shows everything for that synth, including what the main Studio pages already show (macros, engine params, and the instrument's filter, drive, level, pan, tune and ADSR, which are the instrument's own settings, the same values as on INSTRUMENT and MODS), and both pages edit the same values, so a change on one shows on the other and no switching back is needed. A synth's own envelopes (DX7 operator envelopes, Plaits' LPG decay, DCO POLY's envelope) are separate controls that act before the instrument's ADSR, and the page labels them so. Both FM SYSEX and the Dexed DX7 get their full controls here. **Synth control commands (agreed 2026-11-19):** phrase commands that set a synth's macros A/B/C and its params from a phrase step (absolute), with optional smoothing, so timbre, morph and the rest can move inside a song; ChooChooTracker (MIT, read 2026-11-19) has one set per engine (Braids `BMD/BTM/BCL`, Plaits `PMD/PHA/PTM/PMO/PAX`, Plaits trigger decay and colour `TDC/TCL`, FM operator commands, and so on). The spec decides one generic set (macro and param number) or per-engine sets, and the engines imported from ChooChooTracker (MIT, read 2026-11-19) bring their commands along.
- **More mod targets (agreed 2026-11-19):** the instrument's 4 mod slots (LFO, ADSR, AHD, DRUM, TRIG, TRACKING, SCALAR; `songcore/model.h`) can today move volume, pan, pitch, fine pitch, filter cutoff and resonance, sample start and another mod's amount or rate. Add targets: **reverb send, delay send, drive, crush** (and EQ if the spec finds it cheap), and **synth macros A/B/C and synth params** (with the Advanced Synth Studio's synth control work). Each new target is wired into the existing per-voice mod path, smoothed so it never clicks, and named in the MODS screen and its help. Until then, tables with `REV`/`DEL` and the other commands are the way to sweep sends. The spec decides whether track faders and mixer settings become targets too (they are per track, not per note), and checks the CPU cost of synth-param modulation on the weakest handheld.
- **Sample editor gaps (found 2026-11-20, to brainstorm):** compared with Polyend Tracker, M8, picoTracker/LGPT, Digitakt, OpenMPT and Schism (from knowledge; (?) = unverified). Missing: multi-level undo/redo (medium; capped on handhelds); loop points drawn and edited on the waveform instead of 0-255 instrument fractions (medium); loop crossfade for click-free sustain loops (medium); fade curves (exp/log) and crossfades at cut/paste joins (small); mix-paste and paste-over (small); insert silence and auto-trim silence (small); more destructive effects: filter LP/HP/BP, reverb, delay, chorus/flanger, compressor/limiter, as in Polyend (medium each; reuse the engine's); threshold-triggered recording with input gain and monitor (medium; check the recorder first); resample to an explicit rate such as 22.05k/11k (small); free varispeed in cents outside SYNC (small); draw mode for single-cycle waves (medium, low priority); mono to stereo and L/R swap (small); wavetable export, ties to P WAVETABLE bank 4 (medium); slices written into a phrase as one note per step (medium, (?)).
- **Tempo-change command `TPO` (agreed 2026-11-19):** a phrase command that sets the song tempo from that step (for ritardandos, section changes, half-time drops); the MOD, XM and IT importers need it for their speed and tempo commands. None of our 53 commands changes tempo today (grooves only change swing), and ChooChooTracker (MIT, read 2026-11-19) has none either. Small. Help: its SELECT and FX help entries and the manual.
- **Phrase commands from ChooChooTracker (agreed 2026-11-19):** ChooChooTracker (MIT, read 2026-11-19) has 179 commands against our 53; most are tied to its own synths and chips and arrive with those items (see the synth items, layer, inserts, Advanced Synth Studio). The general ones we lack, each added with its SELECT help, FX helper line and manual entry, names to be settled in the spec: **VSL** volume slide (changes volume by an amount per step, continuously); **PRO** probability (the row plays with a 0-100 % chance; conditions on a row combine); **RNN** random note (plays a random note: mode and range); **RNS** random slice (plays a random slice in slice mode); **EUC** Euclidean retrigger (X hits spread over Y+1 rows, looping, until a new note, OFF, KIL or EUC); **REP / RTO** repeat the previous FX with a signed step per row, between limits (ramps without typing every row); **SPD** per-track speed (×1, ×2, ÷2, kept until the next SPD: half-time or double-time on one track); **SLE** smoothing for parameter changes (00 instant, else a glide in ticks, for synth and engine commands); **GGR** global groove (one groove for every track at once; ours `GRV` is per track); **SNG** song hop (jump N rows in the song); **TBX / TXH** a second, auxiliary table per note and its hop (two tables running at once); **TPN** track pan (sets the track's mixer pan, kept until changed; ours `PAN` is per note); **EAT / EDC / ESU / ERL / ESH** envelope attack, decay, sustain, release and shape for this note; **M1A-M4x** modulation slot commands (offset a mod slot's amount and its parameters); **MRT / MKL** retrigger or stop chosen modulation slots; **SEN** sample end for this note; **SLP** sample playback mode for this note (forward, reverse, loop, ping-pong); **SSP** sample speed 0-500 %; **NOF** note release after N ticks (their `OFF`; ours `KIL` cuts, so the spec checks whether a soft release command already exists before adding it). Already covered by ours (not added): RET → `RPT`, DEL → `LAT`, SST/STA → `OFF`, SCL → `SCA`/`SCG`, CRD → `CHD`, BEG/END → `AUS`/`AUF`, RSN/DSN → `REV`/`DEL`, MC1-4 → `CCA`-`CCD`, MOD → `NTH` (the spec checks NTH covers pass A of B), PIT, FIN, VOL, PAN, SLI, NTH. Their help text (`tracker/src/screens/help.cpp`) is a reference for ours.
- **Maqam microtones (agreed 2026-11-19):** each scale note's cents offset, already stored in songs and `.pts` files (`Scale::offset`, `songcore/model.h`, −2400..+2400 cents) but not played or shown today, becomes real. A note snapped by a scale plays with its degree's offset: exact on samples (each chord note too, through its own ratio) and on synths (they take a frequency); SoundFonts through TinySoundFont's per-channel tuning (`tsf_channel_set_tuning`, one channel per track), where a chord shares one tuning and a release tail shifts when the next note retunes, unless the spec adds a guarded per-note tuning to TinySoundFont; external MIDI only approximately (pitch bend). The SCALE screen gains a cents column per note. NAME gains maqam presets (Rast, Bayati, Saba, Sikah, Huzam, Hijaz, Nahawand, Kurd, Ajam and others) with standard offsets that can be adjusted for regional intonation. Phrases mark notes that sound shifted. Chords (`CHD`, the chord editor) follow the scale's offsets. A scale holds one version of each note; maqams that change mid-passage switch scales with `SCA`. Old songs are unchanged (every offset 0). The spec decides how the cents travel from the sequencer to the voices (notes are whole semitones there today; the event layout is checked against goldens) and writes the help.

- **New Note Action (Impulse Tracker style):** what a note does when the next one starts on its track. Two INSTRUMENT rows: `NNA` CUT (default, today's behaviour) / OFF (plays its release) / FADE / CONT (keeps playing), and `DUP` (what the same note again does: off / cut / release / fade, so pads and hi-hats don't pile up). One new phrase command `NNA xy`: x acts on the notes already ringing in the background on this track (leave / cut / release / fade), y overrides the instrument for this note. `OFF` and `KIL` keep acting on the current note only (to confirm in the spec). Old notes ring in background voices; when there are none free, the quietest is dropped. Separate from the later voice-capacity setting in Settings (how many voices a device may use), which decides how many background voices there are.
- **Voice capacity setting (future):** a SETTINGS row for how many voices this device may play at once. NORMAL (the default) is exactly today's 8 song voices plus the preview voice, so small handhelds and existing songs are unchanged; higher steps let stronger devices (Windows, Android, strong handhelds) use more CPU. A device setting, not saved in the song. It pays for New Note Action's background voices and, later, chords on synths beyond the chord engines; when full, the quietest voice is dropped instead of the sound breaking up. The spec decides the steps per platform and whether the app warns when a song wants more voices than the device allows.
- **Resample options box + DRY:** RESAMPLE (a SONG selection, then A,A) first opens a small options box, then the name keyboard as today. This item builds the box and its first row, `DRY` OFF/ON. OFF (the default) is today's mix. ON renders the selected tracks with no reverb or delay returns, no master EQ, OTT, DUST or Studio master rack, no PERFORM filter and no master fader; it keeps the instruments' own sound and the track faders, and the safety limiter (the file is 16-bit). The box remembers its rows between uses. The status says `RESAMPLED DRY -> INST xx` when DRY was on.
- **Resample: normalise on render:** a row in the resample options box, `NORMALIZE` OFF/ON (OFF by default). ON raises the finished sample to a peak target (the sample editor's Peak Normalize, -1 dBFS unless the spec decides otherwise), so no trip to the sample editor.
- **Resample: load as instrument:** a row in the resample options box, `LOAD INST` ON/OFF (ON by default, today's behaviour). OFF only writes the WAV to the Resampled folder and leaves the instruments alone, with a status that names the file.
- **Resample: bit depth (agreed 2026-11-18):** a row in the resample options box, `BITS` 16 (default, today's) / 24 / 32F, the artist's choice. 16-bit gets TPDF dither instead of today's truncation (`songcore/wav_writer.h`). The spec decides whether the song's WAV export gets the same choice.
- **Per-track insert effects (agreed 2026-11-19):** each track gets its own effect slot(s), after its instruments and before the sends: compressor, distortion, tape, chorus, flanger, phaser, rotary, saturation, bitcrusher, parametric EQ, trance gate, Beads granular, formant, stereo width (the list in ChooChooTracker (MIT, read 2026-11-19), `chipnomad_lib/insert_fx.*`, `external/insert_fx`: Airwindows, OTT, TapeScam, JM Formant, Beads; each licence confirmed in the spec). The spec decides how many slots per track, where they are edited (MIXER), their automation from phrases, and the CPU budget per device. **Sidechain (agreed 2026-11-19):** the insert compressor can listen to other tracks (a sidechain source per track, and tracks left out on the master), so the kick ducks the bass for real; ChooChooTracker (MIT, read 2026-11-19) does this (`insert_fx.cpp`, `sidechainSourceMask`). **Phrase commands** set each insert's parameters (their `F11`-`F28`).
- **Layer instrument (agreed 2026-11-19):** an instrument that plays up to 3 other instruments on one note, each with its own transpose (as in ChooChooTracker (MIT, read 2026-11-19), `InstrumentType::Layer`), for thick sounds without spending tracks. The spec decides how it counts against voices and how it shows on INSTRUMENT. **Phrase commands** set each layer's tuning and level per note (their `L1C`/`L1V`-`L3C`/`L3V`).
- **Live audio input on a track (agreed 2026-11-19):** a mic or line input played through a track in real time, with that track's effects, volume and sends (as in ChooChooTracker (MIT, read 2026-11-19), `audio_input_voice.h`). Today recording only goes to a sample, and the Linux recorder has no path to the output on purpose. The spec handles feedback and latency (headphones advised) and which platforms have it.
- **Track bounce (agreed 2026-11-19):** record one track to a sample while the song plays, including live tweaks (as in ChooChooTracker (MIT, read 2026-11-19), `track_bounce.*`: a lock-free ring from the audio thread to a writer thread). RESAMPLE stays the offline way.
- **Live stick (agreed 2026-11-19):** a handheld's analogue stick as a performance controller (filter, macros, PERFORM targets), as in ChooChooTracker (MIT, read 2026-11-19) (`chipnomad_lib_live_stick.*`). The spec maps it onto PERFORM's controls.
- **Automation recording (agreed 2026-11-19):** with record armed and the song playing, moving a mapped knob writes its movement into the playing phrase as that parameter's command on each step it passes, so playback repeats it; smooth stretches can be tidied into an `AUS`/`AUF` ramp. Works with MIDI controllers learned with R + knob (`songcore/midi_map.h`) now, and with the handheld's analogue stick once "Live stick" exists. Records anything a knob can be learned to and a phrase command can set (today: volume, pan, sends, track and master faders, filter, drive, fine tune, delay time, EQ slots; later the envelope, synth control and insert commands). Today knob moves change the live value only, and PERFORM's controls are not recorded. The spec handles: one value per step (finer movement belongs in tables), the three effect columns (never overwrite the user's commands: use a free column or warn), phrases used elsewhere in the song (warn, or record into a copy), undo through PHRASE's history, and whether PERFORM's knobs record too.
- **LSDJ song import (agreed 2026-11-19):** open LSDJ songs (.lsdsng / .sav) as a copy in TrackWerk's own format, as M8 songs are today (reference: ChooChooTracker (MIT, read 2026-11-19), `lsdj_format.h`). Best after the Game Boy chips item, so pulse, wave and noise instruments get the real chip sound. The result is close, not identical: LSDJ's own command and table behaviour is translated, drum kits live in the LSDJ program (ROM) and are not in the song file, so kits need the user's own kit samples, and the import writes a report of what changed, as the M8 import does.
- **MOD import (agreed 2026-11-19):** ProTracker / Amiga modules (4 tracks, some 6-8), the largest tracker archive there is: samples, notes and effects (arpeggio, slides, vibrato, volume slides, speed and tempo mapped to tempo and grooves). Fits 8 tracks today. The spec checks whether libopenmpt (BSD-3) exposes samples and patterns fully enough, or reads the format directly (it is simple and documented). Like every import: read into a copy, saved as `.ptp`, the original never written, and a report of what changed (commands translated to TrackWerk's, close but not always identical).
- **LittleGPTracker / picoTracker import (agreed 2026-11-19):** 8-track handheld trackers with the same song → chain → phrase model as TrackWerk, so songs come across nearly one-to-one, samples and instruments included. Like every import: read into a copy, saved as `.ptp`, the original never written, and a report of what changed (commands translated to TrackWerk's, close but not always identical).
- **FamiTracker import (agreed 2026-11-19):** NES songs (.ftm), 5 channels, after the Game Boy and NES chips item so they sound like the NES. Expansion-chip songs (VRC6, Namco 163 and others) that need more than 8 channels wait for 16 tracks, and chips we don't have are reported. Like every import: read into a copy, saved as `.ptp`, the original never written, and a report of what changed (commands translated to TrackWerk's, close but not always identical).
- **Record notes live (agreed 2026-11-19):** play a MIDI keyboard (or the buttons) while the song runs and the notes are written into the phrase in time, plus step recording (one note per step, the cursor moving on). **Shortcut:** ChooChooTracker (MIT, read 2026-11-19) `chipnomad_lib/midi/midi_recording.*`: real-time and step recording, a delay command when a note lands between steps, notes handed from the audio thread to the screen through a lock-free queue.
- **MIDI file export (agreed 2026-11-19):** save the song's notes as a `.mid` (one MIDI track per tracker track, program changes, tempo), to continue in a DAW. **Shortcut:** ChooChooTracker (MIT, read 2026-11-19) `chipnomad_lib/export/export_midi.cpp` on its `smf_file.*` writer. The counterpart of MIDI file import.
- **16 tracks (agreed 2026-11-18, redesigned 2026-11-19):** a song is either 8-track or 16-track; there is no device setting for it. **File extension:** 8-track songs stay `.ptp`; 16-track songs save as **`.pt16`** (any extension length works on Windows, macOS, Linux, Android and FAT32/exFAT cards with long names). Older TrackWerk versions list only the extensions they know, so they never see a `.pt16` and can't open or damage it. The app opens both and switches to the song's track count as it loads. **NEW** asks 8 or 16 tracks in a small box. **PROJECT** gains a TRACKS 8/16 row next to the song's name: 8 → 16 turns tracks 9-16 on and the song saves as `.pt16` from then on (the earlier `.ptp` stays as it was); 16 → 8 is allowed only after one short warning, shown only when something would go: `SONG MAY NOT SOUND THE SAME. YOU WILL LOSE:` followed by only the lines that apply (`TRACKS 9-16`, `FX4-5`, `PHRASES ABOVE FF`, `CHAINS ABOVE FF`, `CHD²/³ CHORDS`); A converts and deletes them, B changes nothing; a 16-track song may stay `.pt16` even with tracks 9-16 empty. In an 8-track song tracks 9-16 show greyed (see wide mode). **Same name, two extensions:** `Song.ptp` and `Song.pt16` may exist side by side; every name check (save-over question, COLLECT, rename) and the autosave treat `.pt16` exactly as `.ptp` today, each within its own extension, and the autosave writes the extension of the song that is open. **Pools (16-track songs only):** 512 phrases and 512 chains (8-track songs keep 256), 256 instruments and 256 tables (still two hex digits). Screens with room show phrase and chain ids as three hex digits (CHAIN's PH column, PHRASE and CHAIN titles; leading zero dimmed); SONG keeps two characters by letting the first one run on past F: `G0`-`VF` mean `100`-`1FF` (G = 10 … V = 1F), drawn with the app's own letters. 512 is the ceiling (two characters can't name more). Pattern-tracker imports must merge identical phrases and report songs that don't fit. **Opening a `.pt16` on a weak device** (the Linux handhelds: Brick, RGB20S, Miyoo Mini/Plus and the other PortMaster targets) first shows a box explaining the device may not play it fully, with sound problems, if the CPU runs out; A opens it, B leaves the open song exactly as it was. Windows, Linux desktop and Android open it directly. **Pages:** SONG, MIXER and any screen whose tracks don't fit (on 4:3, or past the screen's width) show them a page at a time; moving the cursor past the last track on the page turns to the next page, the way the screen map's letters move between screens, and a small arrow on the left or right shows there is another page that way. Open for the spec: what the preview lane (today track 8 + 1) becomes, MIDI and stems for tracks 9-16, and the voice count (16 song voices + preview). Mapped earlier: about 120 places in the code assume 8 tracks; the song format already allows any number of tracks, and phrase / chain refs are plain integers. **Five effect columns (agreed 2026-11-19, 16-track songs only):** PHRASE gets FX4 and FX5 in `.pt16` songs (8-track songs keep three). Wide mode shows all five; on 4:3 FX1-3 stay as today and FX4-5 sit on a small second column page reached by moving the cursor past FX3, with the paging arrow. The three fixed fields (`fx1`..`fx3`, about 20 files: sequencer, `AUS`/`AUF` pairing per column, copy/paste column numbers, Drumlab, HARMONY, help, importers, piano roll, automation recording) become a list. Tables remain the way to run more commands per note. **Chord banks 2 and 3 (agreed 2026-11-19, 16-track songs only):** two more banks of 16 chords, 48 per song (8-track songs keep the one bank of 16). Written `CHD²` and `CHD³`: separate commands underneath, shown as the same name with a small raised bank number drawn in the app's own pixel font (2-pixel blocks, like every glyph; any digit can be drawn). Each takes the same `xy` as `CHD` (chord, voicing). The chord editor walks all 48 slots with the bank in its title; the piano roll's CHORDS tool lists the banks and writes the right command. The value moves a few pixels right to make room for the raised number (tight on 4:3; the spec confirms the layout). Converting to 8 tracks adds `CHD²/³ CHORDS` to the short warning. Example drawn 2026-11-19 on a real PHRASE capture.
- **S3M import (agreed 2026-11-19, needs 16 tracks):** Scream Tracker 3 modules (most use 8-16 channels), sample-based. - **XM import (agreed 2026-11-19, needs 16 tracks):** FastTracker 2 modules (most use 8-16 channels): samples, instruments with envelopes (mapped to TrackWerk's envelopes), notes and effects. More than 16 channels handled as for S3M. Like every import: read into a copy, saved as `.ptp`, the original never written, and a report of what changed (commands translated to TrackWerk's, close but not always identical).
- **MIDI file import (agreed 2026-11-19, needs 16 tracks):** standard MIDI files (.mid): 16 channels map to 16 tracks, played with SoundFonts (General MIDI), notes, velocities, program changes and tempo turned into phrases and chains. The spec decides how note lengths and overlapping notes on one channel (chords) become phrase steps, `OFF` and `CHD`. Like every import: read into a copy, saved as `.ptp`, the original never written, and a report of what changed (commands translated to TrackWerk's, close but not always identical). **Shortcut:** ChooChooTracker (MIT, read 2026-11-19) has a small standalone MIDI file reader and writer (`chipnomad_lib/midi/smf_file.*`: notes, program changes, tempo, text; channels bucketed for tracker tracks).
- **IT import (agreed 2026-11-19, needs 16 tracks and New Note Action):** Impulse Tracker modules, the richest classic format: samples, instruments, envelopes and New Note Action. Songs that use more than 16 channels can't fully fit and are reported. - **Furnace import (agreed 2026-11-19, needs 16 tracks and the chip synths):** Furnace chip-tracker songs (.fur, also older DefleMask songs), today's biggest chiptune community. Channels map to the chip models on the roadmap (AY, SN76489, YM2612 and the other ymfm chips, Game Boy, NES); chips we don't have are reported. Like every import: read into a copy, saved as `.ptp`, the original never written, and a report of what changed (commands translated to TrackWerk's, close but not always identical).
- **Synth voices on spare cores (future, agreed 2026-11-18):** the audio thread stays in charge; each block, synth voices go on a work list that idle helper threads may take, and the audio thread takes whatever is left itself, so it never waits on a helper. Each voice renders into its own buffer and the mix sums them in today's fixed order, so the output is bit-identical with any number of helpers. With no spare cores (or the setting off) nothing changes. Needs: synth voices rendered per block instead of per sample (`engine-mix.cpp` calls `synth.next` per sample today), per-voice meters, scopes and send sums merged after, and timing tests on every platform. Build after the sound items and New Note Action, and only when real devices run short of CPU (PERFORM's PEAK meter). Offline renders could use every core first, with no timing risk.
